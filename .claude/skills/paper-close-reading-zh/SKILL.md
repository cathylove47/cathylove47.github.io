# 论文深度精读工作流（中文）

面向论文精读地图的笔记体系：MRI 重建 + 计算病理（WSI/MIL/多模态/视觉语言）。
现有 12 节模板保持不变，本 skill 定义每一节的**深度达标标准**与**证据规则**。

## 等级定义（Effort Levels）

| 等级 | 目标 | 典型行数 | 适用 |
|---|---|---|---|
| L0 导读 | 12 节齐全、无展开论证 | 38–75 行 | 新增论文先占位 |
| L1 精读 | 公式推导 + 逐模块代码走读 + claim-evidence map | 300–500 行 | 主线必读论文 |
| L2 批判 | L1 + 复现级检查清单 + 领域批判项 | 500+ 行 | 博士课题直接相关 |

升级顺序原则：**一次只升一篇到 L1**；L0 篇目在"与前后论文的关联"节维护指针即可，禁止批量平庸展开。

## 证据规则（硬约束，违反即返工）

1. **Source-Adjacent**：每条对论文的转述，紧邻给出原文出处（Section X.Y / Fig. N / Table N / Eq. (N)）。格式：
   - `【原文】"..."（Sec 3.2, p.4）`
   - `【解释】<紧跟的白话解释>`
   解释与引用交错排列，不允许整段转述后统一补引用。
2. **禁止凭记忆复述原文措辞**；引用计数、venue、代码链接等元数据必须实时核对 arXiv/GitHub 页面。
3. **未解决的图表**：正文引用了 Fig. N / Table N，就必须在该节内给出对它的解读；解读不了，明确写"未核对 Fig. N，待补充"——不允许静默跳过。
4. **公式防编造**：公式必须来自论文 PDF/官方仓库核验。提取不可靠（OCR 乱码、截图模糊）时写"公式需人工从 PDF 核对"，禁止编造符号拆解。
5. **三档结论标注**：论文的每个主要结论标注 `[显式]`（论文明确写出）/ `[隐含]`（由实验可推出）/ `[推测]`（笔记作者判断）。推测必须第一人称署名语气。

## 12 节模板的深度达标标准（L1）

每节在现有骨架上增加以下要求；不改变节名和顺序。

### 0. 零基础导读（所有篇目必需）
- 每篇先提供独立可读的“零基础导读”，默认读者不知道 WSI、patch、MIL、encoder、attention、转录组等术语。
- 固定顺序：生活类比 → 为什么需要 → 四步以内方法流程 → 术语白话定义 → 输入/输出 → 最容易误解之处 → 一句话记忆。
- 类比只解释直觉，必须明确它不是论文结论；不能用类比替代后续精确定义。
- 一句话只讲一个新概念；首次出现的术语立即解释，禁止把多个英文缩写堆在同一句中。
- 第一次阅读只要求读完第 0 节与第 1 节；公式、代码和复现实验作为第二层内容保留，不得用技术密度挡住入门路径。

### 1. 三分钟摘要与推荐理由
- 一句话结论 + "它解决了什么"（3 个 bullet：mean/max/attention 式的对照，讲清 baseline 失败模式）。
- 推荐等级 + 建议投入方式（读什么、跳什么、先跑什么）。

### 2. 论文解决的问题及其研究位置
- **学习问题形式化**：bag/instance、输入/监督/预测粒度表（参考 DSMIL 篇 Table 2.1）。
- 三类方法交点定位：本文在实例式 MIL / 嵌入式 MIL / 自监督表征 / 物理展开等谱系中的位置。

### 3. 核心方法和数据流
- **ASCII 数据流图**必画（参考 DSMIL 篇 §3.1）。
- **关键公式节**：每个公式五要素——
  1. LaTeX 复现；
  2. 逐符号定义表；
  3. 该公式在方法中的角色（损失？聚合？一致性约束？）；
  4. 直觉解释（白话）；
  5. 与方法的连接（去掉它会退化为哪个 baseline）。
- 逐模块拆解：每模块一个小节（输入形状 → 变换 → 输出形状）。

### 4. 关键实验、数据集与指标
- **claim-evidence map**（表格）：每条主要结论一行——主张 | 支撑证据（Table/Fig）| 证据强度 `[显式/隐含/推测]`。
- 指标语义：NMSE/PSNR/SSIM 或 AU/C-index 等在该领域"测了什么、没测什么"。

### 5. 官方代码仓库审计
- 仓库结构树（`tree -L 2` 或 GitHub 页面摘录）+ 复现评级 A/A−/B/B−/C。
- **代码走读**（L1 必须）：选 1 个核心模块（如 `BClassifier.forward`），逐行跟张量形状，写成 "输入 [B,N,D] → ... → 输出 [B,C]" 的跟踪段。

### 6. 环境、显存、存储和数据准备要求
- 并入**可复现性七维 rubric** 表：代码可运行性 / 数据可得性 / 超参完整性 / 训练成本 / 评测协议 / 依赖环境 / 总体难度，各档：容易/中等/困难/无法判断。

### 7. 建议复现路径
- 三层：最小测试 → 标准实验 → 扩展实验（已有格式保留）。
- **Replication-oriented 检查清单**：appendix 超参、数据构造脚本、eval 脚本、pretrained 权重链接、随机种子控制——逐项标"已核对/未提供"。

### 8. 建议代码阅读顺序
- 保留现有链式列表，每项后加一句"看什么"（如 `datasets/generic.py` → 看 bag 切分与患者级划分逻辑）。

### 9. 值得借鉴的思想与可迁移组件
- 组件级迁移（"把 XX 拆开用"），不是思想级复述。

### 10. 局限、复现风险和博士课题切入点
- **至少 2 个具体局限**，禁止"未来可以改进"式空话；每个局限给出它威胁论文的哪个结论。
- 领域批判项（按领域实例化）：
  - MRI 重建：回顾性欠采样 vs 真实加速、跨厂商/场强泛化、临床指标缺失、运动伪影。
  - 计算病理：患者级数据泄漏、编码器主导效应、注意力≠病因解释、染色/扫描仪偏移。

### 11. 与前后论文的关联
- 前置必读指针 + 演进链条（"聚合器如何演进"式叙述）。
- 批量矩阵：同主题笔记 ≥5 篇时，维护一张横向对比矩阵（Citation/问题/方法/数据/主张/局限/Use as）。

### 12. 官方链接
- 论文 / 代码 / 数据与项目页；链接须实时核验可达。

### 末尾新增（不占节号）：自测题
- 1 道概念题 + 1 道反事实题（"如果去掉 X 模块/损失项，性能会退化为哪个 baseline？为什么？"）。

## 写作规范

- 中文正文；术语首现给英文原词。
- 公式一律 `$$...$$`（显示）或 `$...$`（行内）——渲染链已支持 remark-math + rehype-katex。
- 数据流图用 ```text 围栏 ASCII。
- 逐行代码跟踪用 ```text 或对应语言围栏。
- 不确定的信息写 `?` 或"待核对"，禁止编造。

## 工作流（升级一篇 L0 → L1）

1. **收集**：下载 arXiv PDF/HTML + 官方仓库；实时核对元数据（venue、引用格式、代码链接）。
2. **Pass 1 Map**：通读，产出 5C 分诊（Category/Context/Correctness/Contributions/Clarity）+ 依赖排序的阅读顺序；确定"关键公式清单"和"核心模块清单"。
3. **Pass 2 深读**：逐节按 Source-Adjacent 格式重写；公式逐个五要素；代码模块逐个形状跟踪。
4. **Pass 3 批判**：构建 claim-evidence map；填写可复现性 rubric；写领域批判项与自测题。
5. **校验**：`$$` 公式在 SPA 中渲染正确（KaTeX）；所有 Fig/Table 引用都有解读或"待补充"标注；行数 ≥ 300。
