INFERENCE WALKTHROUGH / NOT A REPRODUCTION

同一张噪声，
只换轨迹。

用作者代码与 EDM ImageNet-64 条件模型，固定同一 latent、同一 ImageNet 类别（207 golden retriever），分别用 naive 采样与论文的 ε-greedy 噪声轨迹搜索跑 3 个 seed。分类器奖励从 0.432（0.17–0.65）升到 0.998（0.9975–0.9989），两张图逐像素 PSNR 只有 6.6–9.3 dB。方向与论文一致，幅度更大；只是 1 张图/类×3 seed 的小样本，不是论文指标。

只跑推理EDM backend · ImageNet-64 · class 207 · 3 seeds
01

跑了什么

只跑 EDM backend（--backend edm --scorer imagenet，18 步随机 EDM 采样器）。对比 naive 与 eps_greedy：每步 N=4 个候选、K=20 次局部搜索、ε=0.4、λ=0.15，与论文 Table 1 的超参一致，全部用 main.py 默认值。seed 0/1/2，每 seed 生成 1 张 64×64 图，打印脚本自己的 final average classifier score。

SD backend 没跑：需要 HF stable-diffusion-v1-5 全套权重（数 GB），且与 EDM 结论重复。

02

环境与改动

独立 conda env（python 3.9.23）。与 environment.yml 的偏差：原文件钉 python<3.10 + pytorch 1.12.1，但 torch 1.12 的 CUDA 11.3 轮子不支持 sm_89（4090），换成 torch 2.1.2+cu118、torchvision 0.16.2；transformers 4.57 与 torch 2.1.2 不兼容（缺 _pytree.register_pytree_node），降到 4.44.2。numpy 1.26.4。

权重：EDM edm-imagenet-64x64-cond-adm.pkl（1.18 GB）+ OpenAI 64x64_classifier.pt（261 MB），都从官方 CDN 下到本目录，用 --network_pkl 指向本地 pkl，并把 HOME 指到论文目录让分类器缓存落在 ./.cache。

代码改动 3 处，均为可复现性/环境必需：edm/main.py:13 的无条件 CUDA_VISIBLE_DEVICES="0" 改 setdefault（否则抢卡）；在抽 latent/类别之前 torch.manual_seed（原代码 seed 太晚，naive 与 ε-greedy 会拿到不同类别，无法对比）；新增 --class_label 与 --network_pkl。算法超参未改。

同一 latent、同一类别下，两种方法的像素 PSNR 只有 9.26 / 9.11 / 6.58 dB——差异确实来自噪声轨迹，而不是初始噪声或类别。耗时：naive 18 步约 1.5 s（11–14 步/s）；ε-greedy 每步 7–9 s、18 步约 150 s（每步 20 次局部搜索 × 4 候选 ≈ 80 次网络评估）。GPU 1（24 GB，共享）上逐进程采样峰值 2018 MiB，与 naive 同量级。

naive 的 seed 间波动（0.17–0.65）复现了论文「单次采样的噪声实现强烈影响质量」的动机；ε-greedy 全部挤在 0.998 附近，说明搜索几乎把每个 latent 都推到了分类器的高分区。论文 Table 1 的 naive/ε-greedy 是 0.3778/0.9885（36 张图平均），本走查的单张数值落在同一区间。

没跑的部分与局限

  • 样本量极小：1 张图/类 × 3 seed，只能看方向，不能当作论文的类平均/FID 指标。
  • 奖励与评测同源：用分类器概率当奖励又用它评测，只能说明「搜到了分类器喜欢的方向」。
  • SD backend 未跑：CLIP/brightness/compressibility 奖励、文生图与 SDXL+ImageReward 都没验证。
  • 基线不全：只跑 naive 与 eps_greedy，MCTS / beam / zero-order / rejection 未跑，无法复现论文的对比表。
  • 环境偏离：torch 从 1.12.1 换到 2.1.2，数值可能与论文略有差异（超参未动）。
