PAPER STUDY 12 / MEDICAL AGENTS

让医学 Agent
从失败里长出新能力。

医学 Agent 的智力通常是「通用推理模型 + 一组人设计好的工具」，部署那天就固定了。MedRSI 换了个起点：让 Agent 自己看失败、按临床后果挑要修哪个错、写代码或训小模型造出候选工具，先放进实验池，只有在后续多个患者队列上持续获益且不抬高临床代价，才写进常驻工具箱。这一轮注册的工具会改变下一轮能看到的证据——这就是「递归」的含义。

01

把 RSI 搬进医学，哪里会出事？

自我改进听起来只是「让 Agent 反思并保留好改动」。但在医学里，有两件事会让它变形：错误不等价，以及保留会自我放大。论文的问题分解也照着这两条来：改进什么、保留什么。

麻烦一：按频率排序会学错东西

常见的边界分歧（比如「疑似青光眼」判成「短期复查」还是「常规随访」）出现得最多，对病人的后果却很小；罕见但严重的错误（晚期青光眼被判成正常并出院）出现得少，后果却大得多。如果改进预算按错误频率分配，Agent 会越来越擅长修常见的错，而反复放过后果严重的错。论文的消融给出了量化版本：均匀优先级的配置在训练集上第 20 轮达到 97.8% 平衡准确率，测试集却从第 11 轮起卡在 88.7%——训练—测试差 9.1 个点，而完整框架只有 1.6 个点。

麻烦二：一次保留会污染整条轨迹

工具一旦进入常驻工具箱，规划器会在后续病例里调用它，它的输出进入执行记录，而执行记录又决定下一轮反思什么、发明什么。论文里的纹理评分工具就是活例子：发现队列上 +6.1 个点，随后三个队列 −2.3／−5.4／−3.1；被立即注册后在 81% 的后续青光眼病例里继续被调用，四轮内又衍生出三个对它做后处理的工具，被排序的失败簇也越来越多地来自「它的分数本身就误导」的病例。

一句话记住这篇论文的立场。医学里的自我改进不是「发现得越快越好」，而是发现要快、采纳要慢：候选可以激进地生成与试验，但常驻 Agent 只在收益跨队列持续、且临床代价不上升时才改。
常驻 Agent 的定义：只有工具箱在演化
Hr=(M,P,TrS)H_r=(M,P,\mathcal{T}^{S}_{r})Hr​=(M,P,TrS​)
H_r = (M, P, T^S_r)
论文 Eq.1。M 是多模态推理模型，P 是通用执行工作流，T^S_r 是第 r 轮的工具注册表。M 的参数与 P 的执行规则在整条改进轨迹中固定不变；自我改进只作用于 T^S_r，所以任何提升都能归因到「Agent 现在能获得哪些证据」。
把它读成「换的不是脑子，是手上的器械」。第 0 轮的 Agent 是 OpenHands（一个通用软件/工具使用 Agent，不含任何临床内容），第 20 轮它已经握有 16 个任务专用工具。
02

两个机制：按临床代价排序、按队列证据注册

机制一解决「改进什么」。评分者先回答错没错（e_i），再回答错得多严重（s_i），两者合成一个优先级。机制二解决「保留什么」：候选进池的门槛故意宽松，进注册表的要求则同时看性能与临床代价。

机制一：临床代价感知的优先级
qi=ei(1+λci),ci=si4,si∈{0,1,2,3,4}q_i=e_i(1+\lambda c_i),\qquad c_i=\frac{s_i}{4},\qquad s_i\in\{0,1,2,3,4\}qi​=ei​(1+λci​),ci​=4si​​,si​∈{0,1,2,3,4}
q_i = e_i (1 + lambda * c_i), c_i = s_i / 4, s_i ∈ {0,1,2,3,4}
论文 Eq.7–9。s_i 由评分者按预设 rubric 给出五档：可忽略／轻微／中等／严重／危重；c_i = s_i / 4 落在 [0,1]；λ 控制临床后果的影响强度，默认 λ = 2。对错误预测 q_i ∈ [1, 1+λ]，正确预测的 q_i = 0 但仍可用于评估候选性能。λ = 0 退化成按频率排序，也就是消融设置。
论文的两个青光眼例子：早期青光眼被判成「疑似、短期复查」给 c = 0.25、q = 1.5；已记录晚期损害却判成正常并出院给 c = 0.75、q = 2.5。两者都错，但后者拿到的改进优先级高 67%。

论文 Eq.10，报告时乘以 100，读作「每 100 名患者的临床代价」。因为后果是对每个被比较的 Agent 在同一参考与 rubric 下重新评定的，改进可以有两种方式降低代价：把错误改对，或把错误换成后果更小的残留错误。
这一个公式是整篇论文的黏合剂：它既决定「Agent 选择去修哪些失败」，也度量「修完之后临床上是否真的少犯错」。

机制二（上）：进实验池只要「有一点好处」
ΔPdisc(T)>0\Delta P_{\mathrm{disc}}(T)\gt 0ΔPdisc​(T)>0
Delta P_disc(T) > 0
论文 Eq.13。发现阶段是筛选：目的只是把可能有用的能力留住继续评估，而不是攒够永久采纳的证据。入池即冻结整个候选包（可执行代码、权重、预处理、调用说明、依赖版本），并记录当时的常驻注册表快照；此后的任何改动都会产生带新评估历史的新版本。
宽松是刻意的：发现队列上的好处常常来自那批病例本身的特殊性（成像设备、疾病谱、与现有工具的交互），本就不该当作注册依据。
机制二（下）：注册要看多个后续队列的配对结果
ΔPk(T)=P(HTref⊕T,VT,k)−P(HTref,VT,k)\Delta P_k(T)=P(H^{\mathrm{ref}}_{T}\oplus T,V_{T,k})-P(H^{\mathrm{ref}}_{T},V_{T,k})ΔPk​(T)=P(HTref​⊕T,VT,k​)−P(HTref​,VT,k​)
Delta P_k(T) = P(H_ref_T (+) T, V_T,k) - P(H_ref_T, V_T,k)
论文 Eq.14。第 k 个试验队列里比较两个配置：候选被发现时的常驻 Agent 快照 H^ref_T，与允许规划器调用该候选的 H^ref_T ⊕ T。符号 ⊕ T 的意思是「可用」而不是「必须用」：候选被调用、执行失败、以及规划器选择不调用它的病例都算进评估，所以度量的是「把这件能力加进真实诊断流程」的实际贡献。临床代价的配对变化 ΔC_k(T) 用同一套评分者与 rubric 算（Eq.15）。
配对是关键：患者输入、推理设置与随机种子都匹配，差异只来自「候选能不能被调用」。P 在分类任务上是平衡准确率，在射血分数上是负的归一化平均绝对误差——总是越大越好。
注册条件：性能持续、代价不升
ΔP‾(T)=1K∑k=1KΔPk(T)>δ,ΔC‾(T)=1K∑k=1KΔCk(T)≤0\overline{\Delta P}(T)=\frac{1}{K}\sum_{k=1}^{K}\Delta P_k(T)\gt \delta,\qquad \overline{\Delta C}(T)=\frac{1}{K}\sum_{k=1}^{K}\Delta C_k(T)\leq 0ΔP(T)=K1​k=1∑K​ΔPk​(T)>δ,ΔC(T)=K1​k=1∑K​ΔCk​(T)≤0
mean Delta P(T) = (1/K) * sum_k Delta P_k(T) > delta, mean Delta C(T) <= 0
论文 Eq.16。默认 K = 3 个后续队列；分类任务的 δ = 0.005（0.5 个平衡准确率点），射血分数任务为 0.01 个归一化误差单位。第一个条件要求收益跨队列持续，第二个条件阻止「用更严重的残留错误换总体分数」。K 数的是可评估队列而不是改进轮数，所以候选试验与自我改进并行推进；没有合格队列时候选保持待定，而不是拿不完整证据去注册。
论文给的判定例子：三次试验增益 1.2／0.6／0.9 个百分点，均值 0.9 > 0.5，且代价不上涨 → 注册；发现阶段大涨、随后 +3／−1／−2，均值为 0 → 拒绝。注册还是串行提交的：注册前比对候选记录里的注册表哈希，若期间注册表变过，要在新上下文里重新评估。

五阶段回路：从一批病人到一件新能力

下面是论文 §2.1 的五个阶段。点开每一步看细节；每一步的产物都会进入下一步，而最后注册的能力会改变下一轮的起点。

诊断经验批

产物长什么样？每一步都留下可检查的记录：候选是「可执行代码 + 权重 + 输入输出 schema + 临床调用说明 + 依赖 + 开发记录 + 版本哈希」的制品；开发记录里有架构、损失、优化设置、停止准则、训练数据与选中的 checkpoint。官方仓库把这些都写成普通 JSON 和 Python 文件，没有任何私有格式。

为什么注册要「串行提交」？因为 MedRSI 是累积演化的：一件新能力的效果取决于它进入时工具箱里已有什么。新分割模型会改变下游预测器吃的测量值，新预测器会改变规划器如何使用既有工具。所以注册前要比对注册表哈希，变过就重评；对共享组件的更新要与受影响的依赖函数打包成一个带版本的整体改动。

青光眼这一例的关键是「模态都在，但被独立解释」。结构与功能证据不一致的病例（例如视盘外观正常却已有早期弓形视野缺损）占前三轮被排序失败的 71%。第 1–3 轮先补了 OCT 厚度提取与视野指标解析（升到 81.6%）；第 4 轮反思指出更深的问题，于是自研一个三分支融合网络并对缺失模态加掩膜，发现队列 +6.3 个点、三个试验队列 +5.1／+6.8／+5.6，第 6 轮注册；第 9 轮注册重校准的第二版，最终 92.1%。这个网络在 94% 的测试病例被调用、在 78% 中提供权重最高的证据。

超声心动图这一例的关键是「缺的不是预测器，而是训练数据」。对比剂的信号反转破坏了非对比分割模型（直接套用 nMAE 0.92）；第 2 轮先在 120 例对比数据上训预测器（0.81）入池；反思随后指出真正的瓶颈是只有少量对比训练集，而 2,716 例非对比研究有同类标签却因域偏移不能用。第 4 轮它训练一个图像翻译模型把非对比映射到对比域，用已有的心室分割能力验证解剖一致性，造出 2,716 例继承原标签的合成对比研究；第 6 轮在真实 + 合成数据上联合训练预测器，三个队列 +0.07／+0.10／+0.08，第 8 轮注册。最终 0.55，优于任务专用回归器的 0.66；仅用合成数据是 0.79，说明合成是补充而非替代。生成图像与 42 名有配对真实帧的患者相比 SSIM 0.81。

两个诚实的地方。其一，这两张表里的任务专用对照（融合网络、回归器）由研究团队在同一批标注上训练、开发预算与 MedRSI 的消耗对齐——「预算对齐」不等于「同等调优」，解释权在作者。其二，私有队列与私有参考标准意味着这两行数字无法被外部独立重跑，能复现的只有机制。

今天就能跑起来的那部分

官方仓库是 MIT 协议、纯 Python 核心、无强制依赖，`pip install -e` 之后有一个 `medrsi` 命令行。要改成你自己的任务，只需两个文件：写清任务与后果 rubric 的 `task.json`，以及病例清单 `cases.jsonl`。

run / status / eval

三个 CLI 子命令：跑或续跑改进轮次、查看注册表与实验池、在某个 split 上评估当前或任意历史轮次的快照。

5 类产物

`runs//` 下是 `library/-/`、`rounds/round_00N.json`、`history.jsonl`、`state.json`、`diagnoses.jsonl`——全是普通 JSON 与 Python 文件。

4 种后端

`openai:*`、任意 OpenAI 兼容服务（vLLM／SGLang／Ollama／…）、`anthropic:*`、任意 Python 可调用对象 `py:module:Model`。

代码 + 权重一起哈希

工具 ID 形如 `vertical_cdr@6e0e7ad5`，代码与权重任一改变都指向另一个包；候选在带超时限制的子进程里训练与检查，崩溃或卡死不会拖停主回路。

三个复现时才发现的坑。1) 论文的 STATISTICS 里说标定集用加权 κ 汇总序数一致性，但正文与表格都没有给出 κ 的数值——你自己的评分者必须重新标定并报告这个数。2) 正文里神经视网膜缘纹理候选的「平均试验增益 −1.2」与同一段给出的队列贡献 −2.3／−5.4／−3.1（均值 −3.6）对不上，论文没说明换算关系，引用时要标注原样。3) 论文只扫描过 δ 的两个取值与 K 的四个取值（Fig.6b：1、2、3、5），δ 本身没有扫描——把它当作敏感性分析的自变量。
07

带走什么，警惕什么

可迁移的不是某个网络结构，而是一套「改什么 / 留什么」的治理结构。把失败按后果而不是频率排序，把发现与注册拆成两个不同门槛，把每件能力冻结成代码 + 权重的可检查制品，并且注册前用后续队列而不是发现队列做配对判定。这四个动作与医学无关、与模型无关，任何高风险域的自我改进系统都能照搬。

已被证据支持的部分。两个公开任务上的完整指标面板来自 5 条独立轨迹，带患者级 bootstrap 置信区间与配对置换检验（第 0→20 轮 P < 0.001；对重跑的 MedAgent-Pro 分别为 P = 0.004 与 P = 0.011）；消融共用同一初始 Agent、患者划分、预算与随机种子，因此归因到机制本身是站得住的；Table 7 的候选账目与正文自洽。

作者主张但尚未验证的部分。临床代价 c_i 是模型评分者按预设 rubric 打的分，标定流程被描述了但 κ 的数值没有公布，rubric 各档位的来源也没有交代，所以「代价不增加」这条注册条件的强度无法从外部估计；长时程只有 30 轮、单一青光眼轨迹；没有前瞻性研究、没有临床医生使用研究、没有患者结局；两个私有任务不可被外部复核；成本只算了加速器小时与推理 token，没有折算货币与临床医生的人力。

  • 如果你只记一件事。「发现要快、采纳要慢」——宽松的进池门槛负责探索，严格的注册条件（性能持续 + 代价不升 + 注册表哈希未变）负责稳定。
  • 如果你要复现。先跑通最小回路，再跑两个消融：`--set lam=0` 看训练—测试差（论文 9.1 个点 vs 1.6 个点），`--set immediate_registration=true` 或 `trial_cohorts=1` 看工具数与后期曲线的「先领先后崩塌」。
    论文同时报告了 K=5 的结果（12 个工具、第 30 轮 94.3%），可以作为「多验几个队列是否值得多等两轮」的对照。
  • 如果你要质疑。先问后果评分怎么标定、κ 是多少、谁写的 rubric；再问「不增加临床代价」在真实临床里对应什么——论文把这一层明确留给了未来工作。
08

合上论文前，检查自己真的懂了没有

01 / 为什么改进预算不能按错误频率分配？

因为错误不等价。边界病例出现得多但后果小，晚期青光眼被误判成正常并出院出现得少但后果严重。按频率分配会让 Agent 学会「训练集里错误的分布」：均匀优先级配置训练集 97.8%、测试集卡在 88.7%（训练—测试差 9.1 个点），完整框架是 95.7% 对 94.1%（差 1.6 个点）。论文还指出，均匀优先级下前十轮 63% 的反思预算花在「疑似」病例上，而完整框架把 58% 花在后果严重的失败上。

02 / 发现与注册为什么必须分开，分开的收益是什么？

因为工具一旦进入常驻注册表，它的影响会超出它立刻服务的那批病人：规划器会继续调用它，它的输出进入执行记录，而执行记录决定下一轮反思与发明什么。立即注册的轨迹在第 8 轮还以 89.6% 领先、工具 22 个，随后一路降到第 20 轮 82.4%、第 30 轮 76.9%（工具 57 个）；完整框架在 30 轮内只注册 18 个工具、维持 94.4%，并拒绝了 43 个「按发现队列就能过关」的候选（其中 29 个在队列试验中平均增益为负）。

03 / 「不增加临床代价」这条注册条件到底保证了什么？

它保证的是「不要用更严重的残留错误换总体分数」：因为它和性能条件用的是同一套冻结评分者与 rubric，且后果是对每个被比较的 Agent 重新评定的。它不保证临床上确定无害——代价是模型评分者给的代理量，论文自己把前瞻性研究、临床医生使用与患者结局列为未来工作。这也是复现时最该补的一个数：κ 没有被公布。

04 / 这个框架改的是什么、没改什么？

改的是工具注册表 T^S_r：Agent 能拿到哪些证据。没改的是 M（推理模型）与 P（执行工作流）——它们全程冻结。所以第 20 轮比第 0 轮强，不是「模型变聪明了」，而是「手上的器械变了」：16 个任务专用工具，其中自发训练的分割模型 Dice 0.87/0.95、vCDR 相关性 r = 0.91。

05 / 两个「未预见任务」的结果有多硬？

机制上讲得通且很具体（多模态融合、生成数据补稀缺训练集），指标也有 5 次运行的 95% CI。但两个队列都是私有的、参考标准也是私有的，外部无法重跑；任务专用对照由研究团队训练，开发预算对齐不等于同等调优。所以这两张表应读作「机制有效性的证据」，而不是「可被第三方验证的结论」。
