PAPER STUDY 03 / COMPUTATIONAL PATHOLOGY

让基因先提问，
再去读切片。

多数病理—基因组生存模型是“各自读一遍，最后再合并”：基因编成一个向量、切片编成另一个向量，拼接或做一对外积就出风险。MIST 把交互提到更早、也更细的地方——每一条基因组特征都拿到一个 token，让它自己去查询切片压出的 4 个组织学上下文 token，补充完毕后才送进 Transformer 预测离散时间生存。结果是：它在结肠、肾、肺、胶质母细胞瘤四个外部队列上，C-index 都高于同骨干的融合基线。

01

多模态融合到底卡在哪？

病理—基因组生存预测的目标很朴素：把两张“图”的信息合起来预测患者结局。切片给出组织形态，基因组给出分子状态，两者确实互补——有些预后信息在任一模态里都看不全。论文 §1；[2]、[3]

论文点出的第一个麻烦是信息融合的位置。已有方法大多在模态级嵌入上定义交互：PATHOMIC 用 Kronecker 积融合组织学图与基因组特征；MCAT 让基因组类别与 patch token 做共注意力；PORPOISE 把泛癌融合规模化；SurvPath 建模通路与组织学之间的稠密交互。它们的共同点是：要么在整患者向量层面合并，要么先把基因组压成粗粒度的分组（通路、基因集）。于是，“单条被观测到的基因组特征如何调制这位患者的切片整合”这件事，被留在了门外。

第二个麻烦是队列现实。在 TCGA 这类队列上训练的模型，要迁移到患者构成、组织制备、切片可得性、尤其是分子检测 panel 都不同的独立机构。外部队列常常缺掉训练时用到的基因：论文里 LUSC 的 TCGA 面板有 197 个突变基因，而外部美国队列只有 22 个，其余全部缺失。模型必须能在“证据不全”时仍然工作。论文 §1、§3.1

第三个麻烦是算力。如果融合意味着让基因组去读数万个 patch 特征，复杂度会随切片分辨率爆炸。基础模型（TITAN、GIGAPATH、TANGLE）先一步把切片压成定长向量，才让“切片侧可查询”这件事变得便宜。MIST 正是站在这一步之上：它不再压成“一个”向量，而是压成一小撮向量，供基因分别取用。论文 §1、§2

晚期融合 / 模态级交互

两位模态各自编码成向量，再用拼接、门控外积或对称共注意力合并。实现简单、容易插拔，但交互只发生在整患者层面：一个基因特征无法单独决定“我该看切片的哪一部分”，形态的分子依赖性也因此难以被表达。

基因组引导的组织学注意力（本文）

每条基因组特征是一个 query，切片上下文是 key/value，交互发生在特征级、编码之前。代价是切片侧被压成 4 个 token 的窄瓶颈（失去 patch 级分辨率），并且需要 TITAN 这类预先算好的切片嵌入。

一句话记住分工。切片侧提供一段紧凑的、可被查询的组织学上下文；基因组侧决定“谁去问什么”；Transformer 负责把补充后的笔记和全局摘要一起读成一个患者表示。
02

基因组 token 怎么去查切片？

先看两侧各自怎么变成 token。基因组侧：每位患者的基因组向量 x ∈ R^d 里，每一条特征独立过一个自归一化网络（SNN）——线性层 + SELU + AlphaDropout——得到 128 维 token，最终组成 E ∈ R^{d×D}，D = 128。用独立权重的好处是特征空间可以逐癌种变化：COAD 643 维、GBM 36 维、KIRC 920 维、LUSC 197 维，互不影响。论文 §2

切片侧：TITAN 把每张 WSI 编成 768 维表示 h_ℓ，同一患者有多张切片就先取平均。论文特意解释：TITAN 是切片级基础模型，训练时就偏向肿瘤与肿瘤邻近形态，所以每个 h_ℓ 已经浓缩了肿瘤相关内容，取平均会强化这份共享信号、压低切片特有的噪声。接着一个线性层同时投影出两样东西：4 个组织学上下文 token C ∈ R^{N_ctx×D}（N_ctx = 4）与 1 个切片摘要 token w ∈ R^D。

为什么是 4？论文给了两条理由：多 token 等于给模型一个小型“可学习字典”，让不同基因组特征可以在其上放不同的注意力权重；而 4 同时是 SHIFT 骨干继承来的注意力头数，保持上下文与架构其余部分同尺度，不用额外调一个新超参。它是一个刻意的窄瓶颈：参数与计算都很小，但足以让交互逐特征发生。

缺失语义要单独说清：自然缺失的基因组特征（保持 NaN）与训练时被 VRM 遮住的位点，都用二值可用性掩码排除出自注意力；当一位患者没有切片、或切片表示被 WSI dropout 丢掉时，交叉注意力整段跳过，并且 w 摘要在 Transformer 输入里被遮蔽，模型只用剩下的可用 token 继续。论文 §2.1

逐条基因组特征变成一个 token

每条基因组特征独立过一个自归一化网络（线性 + SELU + AlphaDropout），得到 128 维 token。特征之间用独立权重，所以特征空间可以逐癌种不同：COAD 643、GBM 36、KIRC 920、LUSC 197。自然缺失的特征保留 NaN，靠二值掩码排除在自注意力之外。

03

训练时的三件小事

结构之外，论文有三处训练设计值得单独记住，因为它们针对的都是“外部队列会变”。第一件是 VRM（variable-rate masking）：自然缺失由原始可用性掩码表示，VRM 再额外遮一层。具体做法是 exact-k 采样——每位患者、每个 epoch 抽一个 k_i，均匀分布在 0 到 ⌊f·d⌋ 之间，然后随机遮住 k_i 个已观测的特征；论文取 f = 0.5。目的是让模型不要把赌注全压在少数几个主导特征上。论文 §2.1

第二件是 WSI dropout：以 p_wsi = 0.3 的概率把整张切片的 TITAN 嵌入丢掉。丢掉的切片绕过组织学富集，对应的切片摘要 token 在 Transformer 输入里被遮蔽。VRM 管的是特征级的基因组缺失，WSI dropout 管的是切片级的模态缺失——两者分工明确。论文 §2.1

第三件是 InfoNCE 对齐：把生存 [CLS] 表示 g_i 与配对的 TITAN 切片嵌入 h_i 分别过两个 MLP 头（Linear–GELU–Linear），投到共享的 D 维空间并归一化，然后做对称对比损失：同一患者的分子与切片表示互为正样本，批内其他人是负样本。它只在 minibatch 里至少有两个样本同时具备基因组与切片时才计算。论文 §2.2

四个癌种的外部证据

评估覆盖四个病理形态与分子检测都不同的癌种：结肠腺癌（COAD）、肾透明细胞癌（KIRC）、肺鳞癌（LUSC）、胶质母细胞瘤（GBM）。TCGA 只用于开发（分层 5 折交叉验证），外部测试集是 CPTAC 提供的公开队列（COAD、KIRC）与两个独立机构队列（LUSC 美国私有、GBM 德国私有）。切片特征全部是预先算好的 TITAN 768 维嵌入；基因组特征空间逐癌种独立保留（来自 LinkedOmics），不强行做泛癌交集，未测值保持 NaN、不做插补。论文 §3.1

特征整理方式值得抄：COAD 取“在 ≥10% 的 COAD-TCGA 样本中发生突变”的 143 个复发突变基因，加 GISTIC2 阈值化 CNV 中方差最大的 500 个基因；KIRC 取 920 个基因级 CNV log2 比值（10% CNV 频率阈值）；GBM 是 IDH1 突变状态加 35 个临床相关 CNV（含 1p/19q 共缺失）；LUSC 用 197 个复发突变基因，而外部队列只剩 22 个。所有特征都用训练集的均值与标准差做 z-score。论文 §3.1

再看风险分层。把五折模型的风险分数平均后按中位数二分，只有 KIRC-CPTAC 的 KM 曲线显著分离（C-index 0.651，95% CI 0.524–0.784，log-rank p=0.0098）；LUSC-US 是趋势级（0.595，p=0.0636）。COAD-CPTAC（0.699，p=0.4478）与 GBM-German（0.586，p=0.1594）都没到显著。论文的解释是：事件数少、删失重的队列里，分层检验比折内排序指标更敏感，这两组分析是互补而不是互相替代。论文 §4.2；Table 3

唯一一列 MIST 输给基线的地方是表 2 最右侧的配对 GBM 控制：只保留同时有切片与基因组的患者后，训练集从 532 人缩到 276 人，MIST 为 0.491±0.08，而 Co-Attn 是 0.555（表内粗体，该列最优）。论文的读法是：这个子集恰好消掉了 MIST 的 VRM、WSI dropout 与基因组引导注意力本来要利用的模态异质性，所以它体现的是设计取向——用在小而人为完整的子集上的边际性能，换取在不完整真实队列上的稳健泛化。这个解释合理，但它同时说明：**如果目标队列是“所有人都配齐模态”，MIST 的收益并不成立。**论文 §4.1

07

你应该从它带走什么？

最可迁移的不是某个算子，而是把“谁去查询谁”这件事定位到特征粒度：只要切片侧能压成一小撮上下文 token，基因组侧就能逐条去取用，而不是让两个整患者向量在最后握手。第二个可迁移点是把缺失写进训练分布——VRM 模拟特征级缺失、WSI dropout 模拟模态缺失，两者分工清楚，也和论文强调的“外部队列会变”直接对应。

它的边界同样清楚：切片侧被压成 4 个 token，因此放弃 patch 级空间分辨率与热图式解释；外部队列规模不大、没有纳入临床协变量；两个外部癌种的数据不公开；配对 GBM 控制那一列还给出了一次明确的负面结果。这些都是读这篇论文时必须一起带走的。

一个好的后续问题：
把上下文 token 数 N_ctx 从 4 扫到 1 / 8 / 16，
C-index 与参数量会怎么变——瓶颈到底是限制还是正则？

下面是本站从已核验内容里推出的可检验切口，属于研究机会推断，尚未做新颖性检索，也不代表原作者结论。共同点是：多数可以用公开的 COAD/KIRC→CPTAC 与官方脚本先做小规模验证。

  • 扫上下文瓶颈宽度。--wsi_n_context 是命令行参数（默认 4），因此 1 / 4 / 8 / 16 的扫描几乎不需要改代码。这直接回答“4 是下限还是甜蜜点”，也能看出窄瓶颈是限制表达还是起了正则作用。
  • 把 WSI-only 当显式基线写进主表。KIRC-CPTAC 上 WSI-only（0.627）高于全部融合基线，LUSC-US 同理。把单模态对照与融合基线放在同一栏并明确“最优基线”的定义，是这类论文最容易含糊的一处。
  • 补上临床协变量。论文自己把“融入患者元数据”列为未来工作；年龄、分期、治疗史等落在外部队列里通常可得，加入后 C-index 的增益有多少、是否与组织学注意力重叠，是可回答的问题。
  • 加插补基线。论文把“基于插补的基线”列为未来工作。VRM 与 NaN 掩码走的是“忽略缺失”路线，与“先插补再训练”的对照能说明哪条路线在 panel 结构错配时更稳。
  • 把交叉注意力权重做成可读的证据。注意力矩阵形状是 d×N_ctx：每条基因特征对 4 个上下文 token 各有权重。它不能证明因果，但可以检验“哪些基因特征更依赖切片上下文”，并与已知的分子—形态关联做对照。
反过来读的诚实提醒：配对 GBM 控制那一列（MIST 0.491 vs Co-Attn 0.555）说明收益依赖“模态不完整”这个前提。如果目标场景里所有人都配齐切片与基因组，这篇论文的卖点需要重新论证。
08

合上论文前，检查自己真的懂了没有

01 / “基因组引导”到底引导了什么？方向是单向还是双向？

被引导的是基因组 token：每条基因特征作为 query，从 4 个切片上下文 token 里取回属于自己的组织学补充（Eq.1）。方向是单向的——切片不会反过来读基因，也没有 patch 级空间定位，因此不产出“某基因 ↔ 某块组织”的热图。这一点和 MCAT 的双向共注意力、可可视化热图形成直接对照。

02 / 为什么切片侧要压成 4 个 token，而不是 1 个或几百个 patch？

压成 1 个就退化成模态级融合，基因特征之间无法分开取用；直接用几百个 patch 会让复杂度上去，也与“小巧、可插拔”的目标冲突。4 个提供了一个小型可学习字典，允许不同基因特征给出不同的注意力权重，同时保持融合参数量小，并与 SHIFT 骨干的 4 个注意力头同尺度（不用另调超参）。代价是失去了 patch 级分辨率。

03 / VRM 与 WSI dropout 分别模拟什么缺失？

VRM 是特征级：每个患者、每个 epoch 抽 k ~ Uniform{0,…,⌊0.5·d⌋}，额外遮住已观测的基因组特征，对应“外部面板少了某些基因”。WSI dropout 是模态级：以 p=0.3 丢掉整张切片的 TITAN 嵌入，对应“这位患者没有切片”。两者走的路径也不同：VRM 让位点被掩码排除在自注意力外，WSI dropout 则整段跳过交叉注意力并遮蔽切片摘要 token。

04 / 论文里 MIST 在哪一列输给了基线？这说明什么？

配对 GBM 控制列（只保留双模态齐全的患者，训练集 532→276）：MIST 0.491±0.08，低于 Co-Attn 的 0.555。论文把这解释为“MIST 放弃了小而人为完整子集上的边际性能，换取不完整真实队列上的稳健泛化”。这个解释合理，但读者应该记住它的直接含义：当模态齐全时，本文的核心机制未必优于对称共注意力。

05 / 正文里 “最优基线” 的定义一致吗？

不完全一致。COAD-CPTAC 的 +9.3% 以 Co-Attn-M（0.612）为分母；LUSC-US 的 +7.1% 只能以融合基线 Bilinear-M（0.533）为分母得到，若把单模态 WSI-only（0.545）也算作基线则只有 +4.8%。此外 KIRC-CPTAC 上 WSI-only（0.627）本身就高于全部融合基线。读表时最好自己指定分母。

06 / 站内今天能完整复现论文的哪几列？

只有 COAD→CPTAC 与 KIRC→CPTAC 两列（都有公开数据与随代码发布的驱动脚本）。LUSC→US 与 GBM→German 是私有队列，作者无权再分发。另外仓库不含任何 checkpoint，要从头训练；切片嵌入也必须用 TITAN 自行预提取。
