# 01｜MDAgents：按医学问题复杂度组织单人、会诊与多团队协作

**论文**：MDAgents: An Adaptive Collaboration of LLMs for Medical Decision-Making  
**正式发表**：NeurIPS 2024，Main Conference Track，卷 37，pp. 79410–79452  
**类型**：方法论文；自适应多智能体协作，不是电子病历操作 benchmark  
**阅读范围**：官方论文摘要、§3 方法、§4 实验与结果。以下是中文导读，不是全文逐字翻译。  
**代码状态**：作者公开仓库已核验；本站未执行其环境、API 或实验，不提供复现评级。

## 0. 先认清它是哪一种 Agent

MDAgents 研究的问题是：**给定一道医学问题，应该由一个模型回答，还是组织几个模型讨论，还是让多个团队分阶段汇总？**

它属于多智能体协作框架：系统先判断复杂度，再招募带有不同医学角色的 LLM；中等复杂度任务可以进行多轮讨论和主持人反馈。它不是一个真实医院，也不是能够自行开检查、写处方的临床产品。角色叫“医生”，不代表每个角色都拥有独立训练、经过执业验证的医学模型。

先区分三条路线：

| 路线 | 判断依据 | 本站例子 |
|---|---|---|
| 多智能体协作 | 多角色分工、讨论、复核与信息整合 | MDAgents、PathFinder、WSI-Agents |
| 工具调用型 Agent | 模型决定调用哪些工具，并利用返回结果继续决策 | MedRAX、EHRAgent、MedAgent-Pro |
| 视觉语言模型与检索基础 | 看图回答或按问题筛选证据，但没有上述协作或执行闭环 | SlideChat、HistoSelect；不因名字有 assistant 就归为 Agent |

## 1. 三分钟摘要（中文导读）

基础模型正在成为医学中的有价值工具，但怎样在复杂医学任务中使用大语言模型仍是开放问题。本文提出医学决策智能体框架 MDAgents，根据具体医学任务自动为一组 LLM 分配单人或群体协作结构，其设计借鉴了现实医疗中随问题复杂度调整决策组织方式的做法。

作者在医学知识、诊断和多模态推理 benchmark 上比较不同推理策略，也比较了 LLM 与人类医生对医学复杂度的分类。论文报告：MDAgents 在十个 benchmark 中的七个取得最佳表现；摘要将相对已有最佳方法的提升概括为最高 4.2%，并报告主持人复核与外部医学知识结合带来的平均准确率改善。阅读这些数字时必须同时看实验样本量、基础模型和比较对象，不能解读成真实临床患者受益比例。

**来源**：[正式论文 §Abstract、§4](https://proceedings.neurips.cc/paper_files/paper/2024/file/90d1fc07f46e31387978b88e7e057a31-Paper-Conference.pdf)。这是中文概述，不是原文摘要的逐字翻译。

## 2. 核心方法：四个阶段决定如何协作

### 2.1 它到底怎么做？

原论文 Figure 1 与 §3 把流程分成四步：

1. **复杂度检查**：主持人角色把问题分为 low、moderate、high。
2. **专家招募**：招募者根据复杂度决定角色和团队结构。
3. **分析与整合**：单人作答、多角色讨论或多团队生成报告。
4. **最终决策**：决策者读取相应证据，给出最终答案。

| 复杂度 | 组织方式 | 信息如何流动 |
|---|---|---|
| Low | 单个初级诊疗角色，PCC | 使用提示策略直接回答；这条分支没有多轮会诊 |
| Moderate | 多学科团队，MDT | 先各自判断，再讨论；不一致时主持人检查历史并反馈，可继续下一轮 |
| High | 整合照护团队，ICT | 多团队分阶段生成、累积和整合报告，再形成最终判断 |

这不是“所有问题都调用五个 Agent，再投票”。核心变量是**协作结构随问题变化**。§3.4 的 MDT 讨论有最多轮数与最多对话回合的限制，达成共识时可以提前结束；高复杂度分支强调不同阶段团队报告的整合，而不是无限辩论。

## 3. 输入、输出与可观测状态

**输入**：医学问题，以及该 benchmark 提供的文本、图像或视频信息。  
**输出**：最终答案；中间还产生复杂度判定、招募角色、讨论记录或团队报告。

阅读代码时可按以下状态查找，而不要只看最终 prompt：

- 复杂度分类结果与招募理由。
- 每个角色获得的原始信息是否一致。
- 讨论轮次、谁与谁通信、主持人的反馈。
- 最终决策者看到了哪些原始证据和哪些模型生成摘要。
- API 调用次数、执行时间与停止条件。

这些是复现与分析时应记录的项目，不是本文承诺的标准日志格式。

## 4. 实验读法：十个 benchmark 不等于十次临床试验

§4.1 列出 MedQA、PubMedQA、DDXPlus、SymCat、JAMA、MedBullets、Path-VQA、PMC-VQA、MIMIC-CXR 与 MedVidQA。它们覆盖医学知识问答、诊断推理与医学视觉解释。

**关键样本量限制**：该节写明每个数据集使用 **50 个样本**进行测试；Table 2 的实验使用三个随机种子。不能把整个 benchmark 的原始数据规模当成论文实际推理评估规模。

作者比较了单智能体、多智能体和自适应策略。Table 2 主要使用 GPT-4(V)，MedVidQA 使用 Gemini-Pro(Vision)；其他模型结果放在附录。跨论文比较前必须固定模型版本、样本与可获得的信息。

论文报告低、中、高复杂度分支的平均推理时间分别为 14.7、95.5、226 秒。它们是作者当时环境中的观测值，**不是本站测得的延迟，也不是当前 API 的运行承诺**。多团队结构有明显成本，不能只报告答案准确率。

## 5. 真正值得学的机制

**把是否协作本身变成决策。** 与固定人数辩论相比，复杂度分类允许简单任务避免额外模型调用，复杂任务再增加交互。

**将招募与最终决策分开。** 招募者选择哪些专科角色参与，决策者负责整合输出；二者不是同一职责。

**保留意见分歧。** 中等复杂度任务中的主持人读取讨论记录并反馈。最后的共识是组织流程的结果，不是医学真值；同一基础模型扮演不同角色，仍可能共享同一知识缺口。

## 6. 局限与边界

- **样本小**：每个数据集 50 个样本，排名与增益需要更大样本、稳定划分和区间估计支持。
- **静态问题仍是主体**：很多评估是给定信息后作答，不等于在真实临床环境中自主获取信息或执行操作。
- **复杂度分类可能出错**：把需要多证据检查的问题判为 low，会直接影响后续路径。
- **角色不等于独立专长**：同一底层模型的不同角色可能产生相关错误，更多讨论不保证更可靠。
- **成本必须一起看**：多轮、多团队的推理时长和 API 调用成本可能抵消精度收益。

## 7. 对医学与病理 Agent 阅读的连接

先把本文当作**协作组织的基线**，再对照病理路线中的 Agent 与相关基础模块：

- [PathFinder：WSI 导航与诊断分工](?domain=pathology&paper=22-pathfinder)——切片里下一步看哪里，不只是讨论已有文本。
- [WSI-Agents：多模型专家与核验工作流](?domain=pathology&paper=40-wsi-agents)——区分专家输出、逻辑核验、外部事实核验与最终整合。
- [SlideChat：WSI 视觉语言基础](?domain=pathology&paper=16-slidechat)——可作为感知或回答模块，但模型本身不自动成为协作系统。
- [HistoSelect：问题条件化的证据选择](?domain=pathology&paper=15-histoselect)——可为 Agent 提供选区模块，不把两级检索直接等同于自主行动闭环。

**阅读产出**：画清单人、MDT 与 ICT 的信息流，列出一次最终作答用了哪些模型调用，以及哪些结论来自原始医学证据、哪些来自其他角色生成的文本。
