# 03｜EHRAgent：让模型写代码、执行查询，再根据错误修正

**论文**：EHRAgent: Code Empowers Large Language Models for Few-shot Complex Tabular Reasoning on Electronic Health Records  
**正式发表**：EMNLP 2024 主会，pp. 22315–22339；引用正式主会版本，不是早期 workshop 版本  
**类型**：方法论文；结构化 EHR 工具执行 Agent  
**阅读范围**：ACL Anthology 正式摘要与论文方法、评估；中文导读，不是全文逐字翻译。  
**代码状态**：作者公开仓库已核验；本站未执行代码或访问临床数据库，复现评级为未审计。

## 0. 这篇让 Agent 真正执行了什么

EHRAgent 不是让 LLM 凭记忆回答“某患者发生了什么”，而是让它生成并执行代码，从多张电子健康记录表中查询所需信息。

**自然语言问题 → 表结构与医学知识 → 可执行代码 → 数据库/工具结果 → 修正代码 → 最终答案。**

这条路径有外部环境反馈，因此属于 Agent。它的任务主要是临床数据检索与多表推理，不是自动诊断、开药或改写医疗记录。

## 1. 中文摘要

临床医生常需数据工程师协助从 EHR 系统提取复杂患者信息。EHRAgent 将自然语言临床问题转化为自主代码生成与执行过程，把多表推理建模为工具使用与规划任务。

框架先注入相关医学信息，帮助定位应查询的表、字段和记录；再结合交互式编码与执行反馈，从错误消息中修正最初生成的代码。作者在三个真实世界 EHR 数据集上评估，报告相对最强基线的成功率改善最高为 29.6%。这个数字是具体 benchmark 上的结果，不能解释为临床诊疗效果提升。

**来源**：[EMNLP 2024 正式论文摘要](https://aclanthology.org/2024.emnlp-main.1245/)。本节为中文概述。

## 2. 四个组件怎么配合

| 组件 | 作用 | 要检查的风险 |
|---|---|---|
| 医学信息整合 | 注入医学知识、表和字段元数据，形成查询理解 | 医学术语与数据库实际编码不一致 |
| 示例优化 | 从长期记忆中选择过去成功代码作为少样本示例 | 相似问题不一定具有相同表关系 |
| 交互式编码 | 生成代码并执行，取得结果或异常 | 代码能运行，但查错患者、时间窗或单位 |
| Rubber-duck 调试 | 根据错误类型、消息和位置解释原因，再迭代修正 | 修掉运行时错误，不代表修好了医学语义 |

方法正文中的历史示例检索采用基于 Levenshtein 距离的相似性，而不是默认使用向量 RAG。不要把所有“记忆检索”都当成同一种算法。

## 3. 执行反馈为什么重要

普通代码生成只交付一次程序。EHRAgent 会接收 executor 的错误消息，再由模型诊断根因、修正程序，直到结束标记或达到步数限制。

**可观察状态**包括当前查询理解、表/列选择、示例、程序、执行返回值、异常与调试理由。最终答案必须能追溯到执行结果，不能只引用模型自己写的解释。

成功路径与危险路径要分开：

- **运行时失败**：列不存在、类型错误等，通常可以由执行器反馈。
- **语义失败**：患者范围、事件顺序或医学代码理解错误，程序可能照样执行成功。

论文中的 completion rate 与 success rate 因而不能互相替代。

## 4. 实验：完成程序不等于答对问题

论文在 MIMIC-III、eICU 和 TREQS 上评估，报告成功率 SR 与完成率 CR。

| 数据集 | Success rate SR（%） | Completion rate CR（%） |
|---|---:|---:|
| MIMIC-III | 58.97 | 85.86 |
| eICU | 53.10 | 91.72 |
| TREQS | 69.70 | 88.02 |

**数字来源**：[论文正文的评估表](https://arxiv.org/html/2401.07128v3)，作者报告值，本站未复算。

这组结果最直观的阅读结论是：程序完成率高于最终成功率，Agent 能执行不等于 Agent 能正确解决查询。正文还比较了移除医学信息、长期记忆、交互式编码和调试模块的结果；不要只看最高提升数字，而忽略失败任务仍占相当比例。

## 6. 对医学 Agent 阅读的价值

这篇提供了非常清楚的**行动—观测**定义：行动是执行代码，观测是数据或错误。比起只观察多个角色的聊天记录，这条链更容易定位失败发生在哪一层。

将阅读重点放在三个问题：

1. 生成的计划与真实表结构是否一致？
2. 调试修正的是程序异常，还是医学语义？
3. 最终答案能否用执行结果独立核验？

这些是阅读判据，不是本站完成的额外实验。
