## 原文摘要

> Gastric adenocarcinoma (GA) is a leading cause of cancer-related mortality worldwide, and accurate histopathological subtype classification from whole-slide images (WSIs) is essential for effective treatment planning. While multimodal approaches that integrate pathology report text with WSIs can improve classification, existing methods often depend on computationally expensive transformer architectures and large language models. We propose a multimodal knowledge distillation (MKD) framework that combines a pretrained WSI image encoder and a clinical text encoder using Low-Rank Multimodal Fusion (LMF) to efficiently model cross-modal interactions during training. Each WSI is represented as a bag of patches paired with a slide-level diagnostic caption. The teacher model learns fused image-text representations for subtype classification, while the student model distills this knowledge to enable accurate image-only inference. We evaluate our method on the PatchGastric benchmark dataset and achieve at least 3.35% higher mean accuracy than state-of-the-art approaches, without relying on transformer-based fusion, multi-task learning, or large language models. The source code is available at https://github.com/helomelo1/MKD-LMF.

## 中文摘要

> 胃腺癌（GA）是全球癌症相关死亡的主要原因之一，从全切片图像（WSI）中准确地进行组织病理学亚型分类，对于制定有效的治疗方案至关重要。虽然把病理报告文本与 WSI 整合的多模态方法能提升分类性能，但现有方法往往依赖计算开销高昂的 transformer 架构与大语言模型。我们提出一个多模态知识蒸馏（MKD）框架，它使用低秩多模态融合（LMF）把预训练的 WSI 图像编码器与临床文本编码器结合起来，以在训练期间高效地建模跨模态交互。每张 WSI 被表示为一个图块包，并与一条切片级诊断描述配对。教师模型学习用于亚型分类的图像—文本融合表征，而学生模型把这一知识蒸馏出来，以实现准确的仅图像推理。我们在 PatchGastric 基准数据集上评估本方法，取得了比现有最优方法至少高 3.35% 的平均准确率，且不依赖基于 transformer 的融合、多任务学习或大语言模型。源代码见 https://github.com/helomelo1/MKD-LMF。

> **原文图注**：Figure 1: Overview of the proposed two-stage MKD-LMF framework. WSI patches are encoded and mean-pooled to obtain a bag-level image representation (z_img), while the corresponding caption is passed through a text encoder to extract text features (z_txt). In Stage 1, the teacher network employs a Low-Rank Multimodal Fusion (LMF) module to combine (z_img) and (z_txt), producing a fused representation (z_fused), which is used to train a linear classifier (shared with the student) for gastric adenocarcinoma (GA) subtype classification. In Stage 2, the student network takes only (z_img) as input and learns, via a linear knowledge distillation module, to approximate z_fused generated by the teacher’s frozen LMF module. ## 0. 零基础导读：先读这一节

> 这一节只讲直觉，不要求你懂公式。看完本节和第 1 节就可以先停，需要动手时再往下读。

### 0.1 把它想成什么？

一位病理医生几乎总是先看片子，再写下报告。报告里的字（“中分化管状腺癌”）包含了他看完片子后总结的知识。MKD-LMF 想做的，是训练一个**只看片子**就能达到类似判断的模型：先请一位“同时看片子 + 读报告”的老师学出好判断，再把老师脑子里的“图文混合理解”压缩给学生，让学生**把文字那条输入通道彻底扔掉**。

### 0.2 它为什么出现？

只靠图像训练，模型能用的信号有限；把图像和病理报告一起训练，通常更准。但报告有两个现实麻烦：其一，报告是病理医生**看完片子之后**才写的，临床上要自动化分类时，报告往往还不存在；其二，已有的图文方法（如 PathM3）用一个 12 层的 Query Transformer 加一个冻结的大语言模型来对齐图文，算力开销大。作者的目标是：**训练时享受文字带来的增益，推理时完全不碰文字**，而且不用重型 transformer。

### 0.3 它到底怎么做？

1. 把每张 WSI 的图块用冻结的图像编码器 Phikon 编码成 768 维向量，再**平均池化**成一张切片一个向量 z_img。
2. 把对应报告描述用冻结的文本编码器 BGE-small 编码成 384 维向量 z_txt。
3. 老师用**低秩多模态融合（LMF）**把 z_img 和 z_txt 乘性地融合成 z_fused（128 维），接一个线性分类器做亚型分类，只用交叉熵训练。
4. 冻结老师的编码器、LMF 和分类器；训练一个学生网络 H，**只输入 z_img**，输出一个逼近 z_fused 的 ẑ_fused，再送进**老师那同一个分类器**得到预测。
5. 学生用三项监督一起训：交叉熵（真标签）+ 特征对齐（Smooth L1）+ 软标签蒸馏（KL）。

### 0.4 先认清这些词

- **WSI（全切片图像）**：一整张数字化病理切片，尺寸可达几万像素，无法直接喂进网络。
- **MIL（多示例学习）**：把一张 WSI 当成一个“包”，里面有很多图块（示例），只有包级标签。
- **图块（patch）与包级表征**：切片切成小图块，每块编码成一个向量，再用某种排列无关的聚合（这里是平均池化）拼成整个切片的一个向量。
- **知识蒸馏**：让一个小/受限的模型（学生）去模仿一个大模型（老师）的输出或内部表征。
- **LMF（低秩多模态融合）**：用若干个低秩因子相乘相加来近似“图像特征 × 文本特征”的完整张量积，避免参数爆炸。
- **特征对齐蒸馏 vs 软标签蒸馏**：前者对齐老师的中间表征（ẑ→z），后者对齐老师的输出概率分布（KL 散度）。
- **图像-only 推理**：测试时只给图像，不给报告。

### 0.5 输入和输出

- 训练输入：一批 WSI 图块（300×300，20×）、每张 WSI 一条诊断描述、一个亚型标签（三分类）。
- 测试输入：只有 WSI 图块，**没有描述**。
- 输出：三个亚型之一的类别概率（well / moderately / poorly differentiated tubular adenocarcinoma）。

### 0.6 最容易误解的地方

“学生学会了老师的图文融合”→ 不等于“学生真的读懂了文字”。学生的输入里**根本没有文字**，它学的是**在图像特征空间中复现老师那个融合向量**。因此，蒸馏的效果上限由老师的融合表征质量决定，也无法保证学生掌握了两模态之间真正的因果关系。

**现在只记住一句话：MKD-LMF = 老师用图文融合学得好，再把这套融合表征“教”成一个只会看片子却能做出接近判断的学生。**

## 1. 三分钟摘要与推荐理由

在 PatchGastric（胃腺癌亚型，三分类）上，MKD-LMF 取得 **74.83% ± 1.49%** 的平均准确率，比最强基线 PathM3（71.48% ± 1.30%）高 **3.35 个百分点**，比最强的注意力 MIL 基线 ILRA-MIL（70.16%）高 4.67 个百分点。它的卖点不是“更强的图文对齐架构”，而是：

- **训练用双模态、推理只用单模态**：老师拿图文融合做监督信号，学生只吃图像特征，因此上线时不需要病理报告。
- **轻量**：不用 transformer 融合，不用多任务学习，不用大语言模型；融合只是一个低秩张量分解模块，蒸馏器只是一个残差/多层 MLP。
- **消融干净**：论文把“蒸馏损失的两项分别加/一起加”“推理时用哪种模态”拆开做了对照表，并能看到“图文融合的知识确实被搬进了图像学生”（消融 74.83% vs 纯图像 70.35%）。

读它的理由：这是一篇**结构简单、可完整复现的小体量工作**，非常适合作“多模态知识蒸馏”在研究流程中的最小参照——尤其适合入门者理解“为什么训练时可以多模态、部署时只能单模态”这一常见矛盾，以及“特征级 + logits 级双重蒸馏”这条经典配方。

## 2. 问题及研究位置

核心矛盾：**病理报告是第二模态，信息丰富且常与切片成对出现，但它在临床上是在诊断之后才生成的**——用它做推理等于用未来信息回答现在的问题。要自动化亚型判别，模型必须能在只有切片时就工作。

现有工作在两个方向上都有代价：一类多模态方法（Pathomic Fusion、MCAT、MOTCat、CMTA、PathOmics）需要基因组数据，而基因组测序在常规流程中并不总是可获得；另一类（PathM3）用图文对齐，但依赖 12 层 Query Transformer（由 BLIP-2 初始化）加冻结的 FlanT5-XL 解码器，同时优化分类与描述生成，开销显著。PG-MLIF 虽然也用 LMF，但融合的是图像与基因组，用于生存预测。

本文的位置：**把 LMF 用在“图像—报告”这一对更易获得的模态上，做的是胃腺癌亚型分类**；并用**知识蒸馏**把训练期的多模态优势迁移到推理期的单模态学生，从而绕开“推理需要报告”的问题。数据集沿用 PatchGastric，切分与三分类设定与 CITE、PathM3 保持一致，以支持直接对比。

## 3. 核心方法和数据流

```text
阶段 1（老师，多模态）
WSI 图块 p_i（300×300 → resize 224×224）
    → 冻结图像编码器 φ_img = Phikon（ViT-B/16，d_v = 768）：v_i = φ_img(p_i)
    → 平均池化：z_img = (1/N) Σ_k v_k ∈ R^768
报告描述 c → 冻结文本编码器 φ_txt = BGE-small-en-v1.5（d_t = 384）：z_txt = φ_txt(c)
    → 拼接常数 1：z̄_img = [z_img;1]，z̄_txt = [z_txt;1]
    → LMF（rank r = 128）：z_fused = Σ_{j=1..r} (W_v^(j) z̄_img) ⊙ (W_t^(j) z̄_txt) ∈ R^128
    → 共享分类器 φ_cls（Linear+ReLU+Dropout）：ŷ_T = φ_cls(z_fused)
    → 损失：交叉熵 L_CE；训练完冻结（编码器/LMF/分类器）

阶段 2（学生，仅图像）
z_img → 知识蒸馏器 H（论文：残差 MLP 768→512→512→128）→ ẑ_fused = H(z_img)
    → 复用冻结的共享分类器：ŷ_S = φ_cls(ẑ_fused)
    → L_distill = L_CE + λ_feat·L_feat(ẑ_fused, z_fused) + λ_KD·L_KD(ŷ_S, ŷ_T)
       L_feat = Smooth L1；L_KD = τ²·KL( softmax(ŷ_S/τ) ‖ softmax(ŷ_T/τ) )
       λ_feat = 1.0，λ_KD = 0.5，τ = 2

推理：只用 φ_img + H + 冻结分类器（不含文本编码器、不含 LMF）
```

法要点逐条（数字均来自论文正文/图）：

1. **双阶段、教师冻结**：老师先独立训好（20 epoch，Adam，lr 1e-4，交叉熵），随后整体冻结；学生再训（50 epoch，Adam，lr 1e-4）。学生与老师**共用同一个分类器**，这保证了“学生输出对齐老师输出”是在同一套决策边界下进行的。
2. **LMF 的降参逻辑**：完整张量积融合需要 O(d_f·d_v·d_t) 个参数（768×384×128 量级），LMF 降到 O(r·d_f·(d_v+d_t))。低秩分解同时保留“图 × 文”的乘性交互，而不像拼接/相加那样假设两模态独立。
3. **为什么是三重监督**：论文给了明确解释——只用交叉熵，学生从零开始学蒸馏器、用不上老师学到的结构；只用特征对齐，老师表征里若有冗余信息，可能保不住类边界；只用 logit 蒸馏，又抓不住融合表征的完整结构。三者合起来才既结构忠实、又判别、又有真标签兜底。
4. **可插拔的条件主义**：论文的机制描述是“学生把多模态融合表征当作回归目标来近似”，因此**文本只在训练期作为老师的输入出现**，推理路径完全不经过文本编码器与 LMF。

## 4. 论文证据与实验范围

- **数据**：PatchGastric，原始 991 张 WSI、262,777 个 300×300@20× 图块；使用其中 3 个亚型（well / moderately / poorly differentiated tubular adenocarcinoma），缩减为 **179,285 图块、693 张 WSI**。数据切分为 **20% 训练 / 40% 验证 / 40% 测试**（与前作一致）。
- **主结果（Table 1，仅图像推理，均值±标准差，3 次运行）**：ABMIL 66.67±2.63、CLAM 67.83±1.12、DSMIL 69.02±0.42、TransMIL 67.48±1.16、CITE 69.63±0.91、ILRA-MIL 70.16±1.11、PathM3 71.48±1.30，**MKD-LMF 74.83±1.49**。相对最强基线 PathM3 提升 3.35 个百分点（基线数值取自 PathM3 论文，作者声明设置相同）。
- **消融（Table 2，单次运行）**：老师多模态推理 92.74（临床不可用，仅作上界参考）；学生只用特征损失 73.63、只用 KD 损失 73.13、两项合用 **74.83**；推理模态对照——纯文本 68.76、纯图像 70.35、本文图像-only 学生 74.83。即：学生比纯图像高 **4.48** 个百分点、比纯文本高 **6.07** 个百分点；老师比学生高 17.91 个百分点（蒸馏后仍与老师有可观差距）。
- **超参搜索（Fig. 3）**：λ_KD 在 {0.5, 1.0, 2.0, 5.0} 中取 0.5 最好；LMF rank 在 {16, 32, 64, 128} 中取 r=128 最好。
- **表征可视化（Fig. 4）**：t-SNE 的 Davies–Bouldin 指数（越低越好）为 纯图像 5.2641、纯文本 2.3107、老师 0.7309、蒸馏学生 1.1078——学生明显优于两个单模态模型，向老师靠拢但未达到。
- **范围限制**：单数据集、单癌种，无外部验证（作者在结论中明说）；Table 1 的基线成绩是从 PathM3 论文转录而非本文复跑；**只用 3 个亚型**，未覆盖 PatchGastric 全部 9 个亚型；没有与其他融合策略（如注意力融合、张量融合）的同表对照。

## 5. 复现与审计重点

以下事实来自官方仓库 `helomelo1/MKD-LMF` 的实际文件（main 分支），其中若干条与 README 描述不一致，复现者必须以此为准：

- **README 与仓库实际结构不符**：README 的“Repository Structure”列出 `models/lmf.py`、`models/teacher.py`、`models/student.py`、`utils/losses.py`、`train_teacher.py`、`train_student.py`、`evaluate.py`、`data/dataset.py`；但仓库实际只有一个 `main.py`（含全部模型定义）、`dataset.py`、`extract_features.py`、`run.sh`、`captions_filtered.csv`、`requirements.txt`。**README 里的 `python train_teacher.py ...` / `train_student.py ...` / `evaluate.py ...` 命令在本仓库中不存在**，实际入口是 `python main.py --model {image_only|text_only|concat_fusion|late_fusion|full_method|no_attn_pool|no_lmf|no_mil|distilled_method}`。
- **两阶段在代码里是两套模型类**：`full_method` = `MultimodalLMFClassifier`（老师，`LowRankFusion` + `Linear+ReLU+Dropout(0.3)`）；`distilled_method` 需要 `--checkpoint` 指向已训练的老师，再由 `DistilledClassifier` 加载冻结老师并训练“学生”。`DistilledClassifier.forward_train` 里 `feature_loss = F.smooth_l1_loss(...)`，`kd_loss = KLDivLoss(batchmean)(log_softmax(student/T), softmax(teacher/T)) * T*T`，`T = 2.0`，`distill_loss = feature_loss + 0.5 * kd_loss`；训练时 `loss = CE + distill_loss`，与论文 λ_feat=1.0 / λ_KD=0.5 / τ=2 一致。
- **学生蒸馏器实现与论文描述不完全一致**：`main.py` 里 `DistillationNetwork` 被定义了两次（第二个覆盖第一个，含 2 个 `ResidualBlock`，dropout 0.4），但 `DistilledClassifier` 实际用的是 `hallucinator = Sequential(Linear(768,512), ReLU, Dropout(0.5), Linear(512,128))`——一个**普通两层 MLP**，而非论文图 2 描述的残差 MLP。复现时若要贴近论文架构需要自行改回残差块。
- **默认超参与论文不同**：`main.py` 的 `--rank` 默认 64、`--epochs` 默认 10；论文最优是 rank=128（`run.sh` 用 `--epochs 20` 并额外扫 rank 4/16/32/128）。要复现论文的 74.83% 必须显式设置 rank=128。
- **run.sh 不含蒸馏学生**：`run.sh` 只启动 image_only / text_only / concat_fusion / late_fusion / full_method / no_attn_pool / no_lmf / no_mil 与 rank 扫描（种子 0/1/2），**没有 `distilled_method`** 那一步；蒸馏学生需要自己手动调用 `main.py --model distilled_method --checkpoint <老师 ckpt>`。
- **特征提取细节**：`extract_features.py` 用 `AutoModel.from_pretrained("owkin/phikon")` 取 **CLS token**（`last_hidden_state[:,0,:]`，768 维），图块 resize 224×224 并按 ImageNet 均值方差归一化；文本用 `SentenceTransformer("BAAI/bge-small-en-v1.5")`（384 维）。**注意**：文本特征输出目录默认名是 `features_mpnet`（历史命名残留，实际编码器是 BGE-small 而非 mpnet）；输入 CSV 默认 `captions_final.csv`，而仓库里放的是 `captions_filtered.csv`；图块按文件名用 `scan_id.split("_")[0]` 分组。这些默认值与仓库实际文件名/论文描述不一致，是复现部署时的直接坑点。
- **数据切分**：`load_split` 用 `train_size=0.2` 先切训练，再把剩余一半对半分作验证/测试（即 20/40/40），按 `subtype` 分层，`seed=42`（与 run.sh 的 seed 0/1/2 不同——run.sh 通过 `--seed` 覆盖）。
- **硬件**：README 记录实验在 NVIDIA RTX 6000 ADA（48GB）、512GB RAM、Intel Xeon Gold 6426Y 上完成；`requirements.txt` 仅含基础依赖（numpy/pandas/torch/torchvision/tqdm/Pillow/scikit-learn/sentence-transformers/matplotlib），**未锁定版本**。
- **可复现性分层**：特征已预提取（`.pt` 文件）后，训练老师 + 学生是纯特征级操作、门槛低；但 **Phikon 对 179,285 个图块的全量推理**与 PatchGastric 数据获取是主要前置成本。

## 7. 前后关联

- 与 [CONCH](31-conch.md) 对照（**重点**）：两者都用“图像 + 文本”，但目标方向相反。CONCH 做的是**零样本图文对齐**——把图像和文本编码到同一个共享空间，靠相似度让“类别文字”直接给图像分类，文本**始终留在推理链路里**。MKD-LMF 反过来，文本只在**训练期**出现，蒸馏完成后把文本对齐能力“搬到”图像学生里，推理时**彻底去掉文本输入**。换句话说：CONCH 关心“文字能否直接用于推理”，MKD-LMF 关心“文字的知识能否在不使用文字的情况下被复用”。前者依赖文本模态对齐质量，后者依赖学生能否在纯图像特征上重建融合表征——这正好解释了为什么本文的消融要专门对比“纯图像 70.35% vs 蒸馏学生 74.83%”。
- 与 [PathM3](38-wsicaption.md) 对照：PathM3 也用 WSI + 诊断描述，但走“12 层 Query Transformer + BLIP-2 初始化 + 冻结 FlanT5-XL”的多任务路线（分类 + 描述生成），是本文最直接要超越/heavy 的对照与强基线。
- 与 [CLAM](29-clam.md)、[TransMIL](30-transmil.md)、[DSMIL](03-dsmil.md) 对照：这些纯图像 MIL 是本文 Table 1 的图像-only 基线；本文的增益本质上就是“把多模态知识蒸馏到 MIL 式单模态流程”的收益。
- 与 [PG-MLIF] 类 LMF 工作对照：本文复用 LMF 但换了模态对（图像—报告，而非图像—基因组），并把融合结果用于**分类**而非生存预测。
- 与 [MI-Zero](06-mi-zero.md) 对照：MI-Zero 用文本描述做 WSI 级零样本分类，同样把文本引入病理；但它是“文本在推理期直接使用”，本文是“文本只在训练期被蒸馏”。
