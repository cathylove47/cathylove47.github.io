PAPER STUDY 23 / CARDIAC MRI RECONSTRUCTION

不要从头训练，
把编码器借来就好。

加速 MRI 重建模型是出名的吃数据：换医院、换扫描仪、换序列就掉性能。这篇论文只做了一个动作——把 UNETR 里负责“看图”的编码器换成 CLIP / BiomedCLIP / DINOv2 的预训练编码器，解码器、损失、训练协议一行不改——然后在公开挑战数据上系统比较三种策略：从头训练、把借来的编码器冻住、用 LoRA 只调一点点参数。结论是一个可执行的判据：数据越少越该冻结，数据变多或要跨数据集迁移时适配才划算。

01

从头训练，贵在哪里？

MRI 采集慢，是因为 k 空间必须一条一条地采。加速的办法是少采一些，再让算法把缺的部分补出来。深度学习把这件事实成了数据问题：训练一个网络学会“欠采样图 → 完整图”的映射。但学会的是这一批数据的统计规律——换一台扫描仪、换一个中心、换一种序列，规律就变了。

论文把这个困难写成两句话：重建模型高度依赖数据，并且会在分布偏移下退化。已有的解法是“把视觉基础模型接进重建管线”，但作者指出一个关键缺陷：那些管线同时加进了新的重建模块，于是你分不清涨的那几分到底来自预训练表征，还是来自多出来的那几层网络。论文 §1–2

所以这篇论文的问题被收窄成一个可以干净回答的问题：在同一个解码器、同一套训练协议下，把编码器换成预训练模型，值不值？

常见的做法：多接几个模块

把基础模型的特征接到一个新的重建网络里。工程上通常有效，但架构也变了——两个变量同时动，结论无法归因。

本文的做法：只换编码器

解码器、浅层分支、损失、优化器、早停规则全部保持与基线一致。唯一变化的是编码器的先验来源（from scratch / 冻结 / LoRA）。

顺手记下一个对照的分量。基线的从头训练 UNETR 有 65.7M 可训练参数，冻结基础模型的版本只有 33.7M——少约 49%。这不是“总参数更少”（预训练编码器的权重照样全部加载），而是可训练参数更少：省的是一阶/二阶优化器的状态与反向传播的更新量。
02

只换编码器：把“看图”那一半借过来

所有方法共用一个前处理：多线圈 k 空间先做逆傅里叶变换，再按线圈做平方和（RSS）合成一张幅值图，归一化到 [0,1]，裁或补到 224×224，复制成 3 通道以匹配预训练编码器的输入格式。相位与线圈敏感性不进入模型——这一点很重要，因为它决定了本文与“在 k 空间里重建”的方法是两套口径。论文 §4.2

前处理：从多线圈 k 空间到一张幅值图（论文 §4.2 只给名称，这里写的是标准形式）
x~=∑c=1P∣F−1(yc)∣2\tilde{x}=\sqrt{\sum_{c=1}^{P}\left|\mathcal{F}^{-1}(y_c)\right|^{2}}x~=c=1∑P​∣F−1(yc​)∣2​
x̃ = sqrt( Σ_{c=1..P} | iFFT(y_c) |² )
y_c
第 c 个线圈的欠采样 k 空间数据。
ℱ⁻¹
逐线圈的二维逆傅里叶变换。
P
线圈数。所有线圈图平方求和后开方，得到与线圈无关的单张幅值图。
平方和合成把多线圈数据压成一张与线圈无关的幅值图，因此论文里的模型输入是 224×224×1（复制成 3 通道）。这不是论文提出的新公式，而是它明确写出的前处理步骤，列在这里是为了让“输入到底是什么”不含糊。整张页面的指标都建立在这个前处理之上。

基线是 2D UNETR：224×224 的图切成 16×16 的 patch，得到 196 个 token，投到 768 维，加可学习位置编码后过 6 层、12 头、MLP 3072 的 Transformer。解码器把 token 重新排成特征图，用转置卷积与特征融合逐级上采样（瓶颈 z₆ 逐级并入 z₅、z₄、z₃ 的跳连），从 14×14 恢复到 224×224，最后一层 1×1 卷积出图；另有一条浅层卷积分支直接从输入图提低层特征，注入最后一级解码。论文 §3.1

替换只发生在编码器上。三个候选主干都是 ViT-B：CLIP（图文对比学习）、BiomedCLIP（按论文所述在 PMC-15M 上做过生物医学图文预训练）、DINOv2（自监督，无标签）。两个衔接细节值得记住：

  • 丢弃 class token，只留 patch 表征。重建关心的是空间结构，全局类别 token 反而无关。
  • 融合所有层，而不是只取最后一层。把每个 Transformer block 的潜状态经 LayerNorm + 两层 GELU MLP 融合成瓶颈表征；中间层特征同时当多尺度跳连。论文的理由是要同时保留低层结构线索与高层语义。
  • 网格尺寸要对齐。CLIP 与 BiomedCLIP 天然给出 14×14 token 网格，直接匹配解码器；DINOv2 的 patch 是 14，所以是 16×16，需要在解码前双线性插值到所需分辨率。

03

LoRA：只动一点点参数

冻结的编码器虽然提供了强先验，但它的特征未必与心脏 MRI 完全对齐。全量微调代价大，于是论文用 LoRA：不改动原来的权重矩阵 W，而是额外学一个低秩增量 ΔW = BA，乘上一个缩放系数 γ 加到原权重上。rank r 远小于矩阵维度，所以新增参数量很小。论文 §3.3，Eq.1

Eq.1：把任务增量写成两个小矩阵的乘积
h=Wx+γ ΔWx=Wx+γBAxh=\mathbf{W}x+\gamma\,\Delta\mathbf{W}x=\mathbf{W}x+\gamma\mathbf{B}\mathbf{A}xh=Wx+γΔWx=Wx+γBAx
h = W x + γ · ΔW x = W x + γ · B A x
W
预训练权重矩阵（冻结，不更新）。
A ∈ ℝ^{r×d₂}, B ∈ ℝ^{d₁×r}
两个可训练的低秩矩阵，r ≪ min(d₁,d₂)。论文按 LoRA 原文的做法：A 用 Kaiming 初始化，B 初始化为零——于是训练起点与原模型完全一致。
γ
缩放系数，控制增量相对于原权重的强度。
B 从零出发这一条是关键：训练开始时 h = Wx，模型行为与冻结版逐比特一致；随后 ΔW 才慢慢长出来。所以“冻结”和“LoRA”不是两条平行的路，而是同一条路的第 0 步与后面的步骤——这也是为什么二者的差异可以被读成“适配到底带来了什么”。

插入位置写得很明确：每个 Transformer block 的 query、key、value 投影层，而编码器本体（预训练权重）保持冻结。可训练的集合因此被限定成三块：LoRA 参数、token 融合模块、重建解码器。rank 取 r ∈ {8, 64, 128} 做消融；含融合层与解码器在内，可训练参数从约 34.0M（BiomedCLIP，r=8）涨到 40.8M（CLIP / DINOv2，r=128）。论文 §3.3；Table 5–7

05

低数据与跨数据集迁移：结论会翻转

这是全文最有实用价值的一段。作者在 10× 加速下把训练数据切成 5%、25%、50%、75% 四档（Table 3），又做了双向跨数据集迁移：在一个挑战集上训练，不做任何额外微调，直接到另一个挑战集上测试（Table 4）。论文 §5.3–5.4

在 5% 这一档，适配是拖后腿的：LoRA 版普遍低于冻结版（例如 CMRxRecon2023 的 LoRA DINOv2 为 0.8242，而冻结 DINOv2 是 0.8348）。论文的解读很直接——数据太少，不足以可靠地把预训练表征特化到重建任务上。数据变多之后天平翻转：CMRxRecon2024 上 LoRA DINOv2 在 25%、50%、75% 三档都是最好，75% 时 SSIM 0.8550、PSNR 29.58 dB。

跨数据集迁移则相反：在没有任何微调的前提下，LoRA 一般优于冻结。论文的解读是适配把表征对齐到重建任务，同时保留了预训练里那些宽泛的视觉先验。两个方向的难度并不对称：2024 → 2023 明显容易，2023 → 2024 难得多（论文归因于 CMRxRecon2024 规模与多样性更大、目标分布更难）。

一个反直觉但重要的细节。2023 → 2024 时，LoRA DINOv2 的 SSIM（0.7953）比冻结版（0.8016）低，但 NMSE 明显更好（0.1012 vs 0.1253）、PSNR 也更高（27.6952 vs 27.2070）。三个指标并不总是一致指向同一个赢家。论文在 CMRxRecon2023 的 LoRA 上也出现过同样的分裂。做这类比较时，必须先说清楚“更好”是按哪个指标定义的。
THE ONE RULE TO TAKE AWAY

监督量决定你该冻结还是该适配。5% 数据 → 冻结；数据变多（CMRxRecon2024 的 25%/50%/75%）→ 适配；跨数据集迁移 → 适配通常更稳。这个判据可以直接搬到别的重建任务上先做一次二分实验。

复现现状：官方仓库是空壳，但资产是公开的

论文摘要的末句写着“Code is publicly available at: github.com/Hashmi360/BeyondScratch-CMR”。这个仓库确实存在、也确实公开，但2026-10-13 打开核查时只有一个 README：2 次提交、0 star / 0 fork / 0 watcher，`main` 分支下除 `README.md` 外没有任何文件——没有训练脚本、没有配置、没有权重、没有数据处理代码。README 全文只有一句“Official implementation of … accepted at the ECCVW 2026”。结论：需按全文自实现。官方仓库核查

好消息是自实现所需的资产全部公开：两个数据集来自公开挑战，三个编码器都有公开 checkpoint，重建骨架是 UNETR 语义的公开结构。下面按“拿到什么 → 要自己补什么”列清单。

1 个文件

官方仓库的全部内容：README.md。0 star / 0 fork / 0 watcher，2 次提交（2026-10-13 核查）。

2 个公开挑战集

CMRxRecon2023（120 例训练病例）与 CMRxRecon2024（200 名志愿者）；论文按患者级 70/10/20 划分以杜绝泄漏。

3 个公开主干

CLIP、BiomedCLIP（生物医学图文）、DINOv2（自监督），论文用的是 ViT-B 规模。

复现前必须自己定下、并写进实验记录的六件事。
1. 采样掩码。论文只写“在 4×/8×/10× 加速下实验”，没有给出掩码类型（1D 笛卡尔 / 随机 / 等距）。掩码变了，PSNR/NMSE 会显著变化，跨论文比较必须先对齐这一项。
2. 融合模块的形状。“融合所有 Transformer 层”得到的是一个 (层数 × token) 的张量，如何压成 14×14 的瓶颈、中间层取哪几层当跳连，论文都没有给。
3. LoRA 的具体接法。论文说插在 Q/K/V 投影层，但没说是否使用合并的 QKV 矩阵，也没给 γ 的取值。
4. DINOv2 的网格插值。论文只说 16×16 特征被“双线性插值”到所需分辨率，插值前是否重排成 2D、是否裁剪，需要自己决定。
5. 数据切分与预处理粒度。CMRxRecon2023 只有 120 例病例，论文切出 2,940 个训练样本——切分单位与筛选规则（哪些模态、哪些视图）需要自行固定并公开。
6. 方差。论文只报单次结果，没有均值/标准差/显著性检验；而 LoRA 的收益常在小数点后第三位。复现时至少跑两个种子。
评估口径的三个提醒。一，所有指标都在留出测试集上用验证最优 checkpoint 计算，训练过程最多 300 epoch、batch 8、SSIM 损失、AdamW（from scratch 与 LoRA 为 lr 1e-4 / wd 1e-2，冻结版为 lr 2e-4）。二，“可训练参数更少”不等价于“总参数更少”：预训练编码器照样完整前向。三，论文自己声明评估只用平均 SSIM 与 PSNR、没有放射科医生参与，因此任何改善都只是经验趋势，不能当作临床优越性的证据。
08

你应该从它带走什么？

最可迁移的不是某个网络，而是一个实验设计的骨架：固定解码器与训练协议，只把编码器的先验来源当作自变量；同时准备一个参数量可比的从头训练对照；然后把评估沿两个轴切开——监督量（5%→100%）和分布（同数据集 / 跨数据集）。这套骨架能直接回答“我手上的标注够不够支撑自己训一个编码器”。

它的边界同样清楚：没有外部中心验证、没有放射科评估、指标只到 4×/8×/10×、没有方差报告；LoRA 的收益常常在小数点后第三位；官方仓库没有代码，所以“可复现”目前只是资产公开而实现未发布。

一个好的后续问题：
如果把这个“只换编码器”的骨架搬到
低场 MRI 或非笛卡尔采样上，
“5% 冻结 / 数据变多再适配”这条分界线会移动到哪里？

下面是本站从已核验内容里推出的可检验切口，属于研究机会推断，尚未做新颖性检索，也不代表原作者结论。共同点是：每一条都能用公开数据与公开 checkpoint 先做小规模验证，且都能写进你自己的实验记录里。

  • 先坐实掩码这个变量。在固定 4×/10× 条件下，比较 1D 笛卡尔与随机掩码下三种策略的强弱是否翻转。论文没给掩码，所以任何后续工作都必须先对齐这一项，顺手也就成了你自己的基线。
  • 把“冻结 vs 适配”的分界线画细。论文只在 10× 加速下扫了 5%/25%/50%/75%。把扫描同时做在 4× 与 8× 上，就能回答一个更实用的问题：这条分界线随加速倍数怎么移动？成本主要是训练轮次，不是新方法。
  • 区分“指标改善”与“结构改善”。论文多处出现 SSIM 与 NMSE/PSNR 指向不同赢家的情形。加一个结构敏感、且不依赖像素配准的度量（例如分割掩码边界的一致性），可以检验 LoRA 带来的到底是感知上更锐利，还是解剖结构更正确。
  • 把 LoRA 换成别的参数高效方案做对照。目前只有一种 PEFT 实现被评测。换 adapter、visual prompt tuning 或只调 LayerNorm，可以验证“适配的收益来自容量”还是“来自特定的低秩参数化”——这正是 Table 5–7 里 rank 曲线想要回答但没答完的问题。
  • 补上方差与显著性。两个种子的重复运行会把“LoRA 到底有没有赢”从千分位噪音里拉出来。这是最便宜、也最容易被审稿人追问的一条。
09

合上论文前，检查自己真的懂了没有

01 / 为什么这篇论文能说“增益来自预训练表征”，而之前的工作不能？

因为它把变量收缩到只剩编码器：解码器、浅层分支、损失、优化器、早停规则全部与基线一致，并且提供了架构相近、参数量更多的从头训练 UNETR（65.7M vs 33.7M）作为对照。之前的工作往往在接进基础模型的同时也加了新的重建模块，两个变量同时变化，无法归因。

02 / 冻结和 LoRA 哪个更好？

没有唯一答案，取决于监督量与目标分布。5% 数据时冻结更好（数据不足以可靠地特化表征）；CMRxRecon2024 上数据变多后 LoRA 反超（25%/50%/75% 上 LoRA DINOv2 最好）；跨数据集迁移时 LoRA 一般更优。论文的表述是“冻结提供最强的归纳偏置，适配随监督增加而越来越划算”。

03 / Table 2 里 LoRA 的 SSIM 带了 ↓，是不是说明 LoRA 变差了？

要看指标方向。同一张表里 NMSE 也用 ↑ 标注，而 NMSE 下降才是改善——箭头只表示相对冻结版的数值升降。CMRxRecon2023 上的典型模式是 PSNR 与 NMSE 改善、SSIM 略降；CMRxRecon2024 上则是三个指标一起改善。

04 / “参数更少”到底少在哪里？

少的是可训练参数：冻结版 33.7M vs 从头训练 65.7M，差约 49%。预训练编码器的权重仍然全部被加载并参与前向计算，省的只是优化器状态与更新量。LoRA 版在这个基础上再加 0.3M–7.1M（r=8 到 r=128）。

05 / 现在能直接复现这篇论文吗？

不能。论文自述的官方仓库只有 README.md，没有任何实现、配置或权重（2026-10-13 核查），所以只能按全文自实现。数据集与三个预训练编码器都是公开的，因此自实现可行，但采样掩码、融合模块形状、LoRA 的 γ 与 QKV 接法、DINOv2 的 16×16→14×14 插值方式等细节论文都没给，必须自己决定并写进实验记录。
