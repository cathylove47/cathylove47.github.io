01

跑了什么

三个配置各跑一遍：source（不改编码器、不重估统计量）、norm（测试时只重估 BN 统计量）、tent（重估统计量 + 熵梯度更新通道仿射参数）。损坏覆盖全部 15 种（gauss、shot、impulse、defocus、glass、motion、zoom、snow、frost、fog、brightness、contrast、elastic、pixelate、jpeg），severity 只取 5，每类 10000 张。cfgs 默认跑 5 个 severity，这里用 CORRUPTION.SEVERITY "[5]" 收窄，以便直接对齐 README 的 severity-5 表。

02

环境与改动

conda 环境 python 3.8；torch 2.1.2+cu121、torchvision 0.16.2+cu121（4090 不支持仓库时代的 torch 1.8.1，按最低改动升级）；yacs、iopath、requests、pandas、pyarrow；robustbench v0.1 手动 clone；top-level import 需要 autoattack，从 fra31/auto-attack clone 后本地安装；setuptools<70（否则 torch 2.1 的 pkg_resources 报错）。代码零改动。

数据不走 zenodo 原始 2.9 GB tar（实测 <1 MB/s），改从 HF 镜像 xinlinzz/cifar10-c 的逐 corruption parquet 下载，再转成 robustbench 需要的 (50000,32,32,3) uint8 npy；镜像缺 zoom_blur，单文件从 YashP54/cifar10-c 补。权重为 robustbench Standard 的 WRN-28-10（292 MB），robustbench 自带下载器拿到的是 HTML 警告页，改用 drive.usercontent.google.com/download?...&confirm=t 重下。

逐损坏类型也与 README 表吻合到 ±0.1 个百分点（README 只给一位小数）。tent 相对 norm 平均降 1.84，对应 README 的 18.6 vs 20.4（−1.8）。最主要的收益来自重估统计量（43.5→20.4），熵目标只再贡献约 1.8 个点。

耗时：每个损坏 4–9 秒（source/norm 约 5 秒，tent 含一次反传约 9 秒），三配置合计约 5 分钟。日志在 logs/{cfg}_261123_*.txt。

04

样例

本记录只有文字日志，没有保存可视化图像，因此这一节留空。这不是遗漏：TENT 的输出就是分类标签，图像层面没有可比的产物；要画「损坏图 vs 归一化后特征」需要另加钩子，本次没有做。

05

没跑的部分与局限

  1. 与论文主表不可比：论文 Table 2 的 14.3 是 R-26 骨干、离线适配；本记录是 robustbench WRN-28-10、逐损坏在线。source 基线本身就差 2.7 个点（43.52 vs 40.8），说明两个实验的模型/协议不同。
  2. 只跑一个 severity：severity 1–4 未跑，README 的均值表也未复现。
  3. 没跑 ImageNet-C：论文的 44.0/42.3 与 TENT-vs-ANT 对比均未涉及；ImageNet-C 需要 50000 张 × 75 个组合，本机带宽与时间不允许。
  4. 没跑数字识别、GTA→Cityscapes、VisDA-C：论文另外三组实验全部未复现。
  5. 数据来源换了容器：parquet → npy 只改存储格式，数值仍是官方 uint8 损坏图像；source 与 README 逐项一致可以证明转换无损。
  6. 小样本含义：这里「小」指的是只覆盖一个 benchmark 的一个 severity，而不是图像数量少；结论只支持「仓库脚本可复现」，不支持「论文的 TENT 增益可复现」。
